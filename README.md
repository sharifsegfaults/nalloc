## `nalloc` - A memory allocator implemented from scratch

`nalloc` is a memory allocator implemented from scratch. It was developed live, in the span of multiple livestreams, on [Twitch](https://twitch.tv/sharifsegfaults). You can find the whole series on YouTube, [here](https://www.youtube.com/watch?v=vuhCJ6rfofw&list=PLL28XU3PhlP0).

The name has no specific meaning. I think the original intention was for it to mean "new malloc", but honestly, it can mean many things.

### Setup
You can find how to use this memory allocator in [`SETUP.md`](SETUP.md)

### Why?
If you're familiar with me or my other repositories, you'll know how much I like to learn by doing. This is just another instance of that principle. I decided to start this project to learn about memory allocators, and learned a lot along the way.

Apart from this, these are some reasons why I started this project (it seems like these 4 things have started to become some sort of personal manifesto):

1. **There is an inherent satisfaction to understanding and learning**: Being curious about something and discovering things on your own is an incredible experience, not only due to the inherent satisfaction of understanding, but because of all the learning that is involved in the process.

2. **Knowledge is power... and efficiency... and optimizations!**: Often times it is necessary to make decisions that will be hidden from the final user, and the STL is full of such decisions! Understanding the "why?" behind them is not only useful for learning (as mentioned previously) but a process that provides one with better decision making and improved awareness when using these concepts/data structures/classes/etc. to perform optimizations, identify situations where things should deviate from the usual approach, and many more things.

3. **Learn by doing (yes, I repeated it, but it's very important)**: In my opinion, there's no better way of learning than by throwing yourself into the void -- things may seem difficult or confusing at first, but it's only through the struggle of coming up with solutions on your own that you understand their reason of being in the first place.


### Rules - No AI

The only rule I decided to impose for the development of this project was prohibiting the usage of AI. The reason behind this decision is the fact that this is a project aimed at learning, as well as recreation.
